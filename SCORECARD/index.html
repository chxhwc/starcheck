    Scorecard¶

    Every check, its weight, and exactly what evidence it reads. Total weight: 72. Score = 100 × Σ(weight × factor) / Σ(weight), where pass = 1.0, warn = 0.5, fail = 0, and skip is removed from the denominator.

    Weights are a budget, not a vote. If a single check can move the score by more than ~7 points, it is probably measuring two things at once.

    发现 discovery — 24¶

    id 检查 权重 判定依据 为什么重要
    desc 仓库描述 5 GitHub API description，长度 20–160 搜索结果和列表页只有这一行，空描述等于不存在
    topics Topics 标签 4 API topics ≥ 10（5 以上给 warn） GitHub 站内搜索的主要入口，零成本
    license 开源协议 3 根目录 LICENSE* / COPYING* 没有协议，公司用户直接跳过
    name 仓库名 2 ≤ 24 字符、可拼写、能直接当命令 名字 = 命令名 = 搜索词
    social 社交预览图 2 存在 social/preview/og-image/cover.(png\|jpg) 分享出去的卡片默认是灰的
    homepage 主页 / demo 3 API homepage 是 URL 唯一能放「点开就能用」的位置
    hook README 首屏钩子 5 前 10 行有 # 标题 + 一句 ≥ 40 字的定位 大多数人只读首屏

    分发 distribution — 7¶

    id 检查 权重 判定依据 为什么重要
    docs-site 文档站 / Pages 2 API has_pages 或 mkdocs/docusaurus/vitepress 多一个能被搜到的入口

    awesome awesome-list 收录 1 README 中出现 awesome-list 链接 最便宜的长期流量

    已知偏差¶

    • awesome 是启发式。 它只检查 README 里有没有 awesome-list 链接，判断不了 你是否真的被收录了。权重 1，不打算修。
    • desc / topics / homepage / docs-site 依赖网络。 本地模式全部 skip， 所以本地分和远程分不能直接比。
    • hook 只看首 10 行。 一个很好的 README 也可能因为一行烂标题拿不到分——这正是 想抓的东西。
    • 它不测「有没有人 star」。 见 docs/index.md。
